# Local Map Platform — Project Context

Version 1.0.0 — see CHANGELOG.md

## What this is
A configurable community map platform for any UK area. Flask backend, Leaflet
frontend, SQLite DB. Runs as a Docker container with a first-run setup wizard.

Area-agnostic by design — all area-specific values live in data/config.json.

## Architecture
```
localmap/
├── server.py              ← Flask app (API, setup wizard, admin, GeoJSON)
├── requirements.txt       ← Flask + requests
├── Dockerfile
├── docker-compose.yml
├── .env.example
├── public/                ← Only directory served to the web
│   ├── index.html         ← Map frontend (boots from /api/config)
│   ├── setup.html         ← First-run setup wizard
│   ├── admin.html         ← Moderation dashboard
│   ├── style.css          ← Shared stylesheet
│   └── logo.png           ← Default/uploaded logo
└── data/                  ← Docker volume mount, persists across rebuilds
    ├── config.json         ← Generated by setup wizard
    └── places.db           ← SQLite database
```

## Setup wizard flow
On first launch with no data/config.json, the root URL serves setup.html:
1. Choose area (postcode/place name → geocode → set centre + radius)
2. Branding (site name, tagline, theme colour, logo upload)
3. Quick links (add external links for local resources)
4. Data import (OSM Overpass API import for the configured area)
5. Review all settings
6. Finish → saves config.json, redirects to map

## Key API endpoints
- GET  /                    → index.html (or setup.html if no config)
- GET  /api/config          → site configuration JSON
- POST /api/setup/save      → save setup wizard config (first-run only)
- POST /api/setup/geocode   → geocode postcode/place name
- POST /api/setup/boundary  → generate boundary polygon from centre+radius
- POST /api/setup/import    → run OSM data import
- GET  /api/places.geojson  → all active places as GeoJSON
- GET  /api/reviews/<id>    → approved reviews for a place
- GET  /api/events          → approved events
- POST /api/submit          → user submissions (rate limited, honeypot)
- GET  /api/admin/stats     → submission counts (requires Bearer token)
- GET  /api/admin/pending   → pending submissions (requires Bearer token)
- POST /api/admin/<id>/approve|reject|delete

## Security
- static_folder="public" (server.py, DB not web-accessible)
- ProxyFix for real IPs behind reverse proxy
- CSP, HSTS, X-Frame-Options, etc.
- Rate limiting: 10 submissions/hour/IP
- Honeypot field on submissions
- Admin: timing-safe token comparison, brute-force lockout (5 fails → 15 min)
- Admin path randomised per instance
- Setup endpoints locked after first config save
